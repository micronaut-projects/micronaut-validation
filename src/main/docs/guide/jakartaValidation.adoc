Micronaut Validation separates the default lightweight validator from the optional Jakarta Validation compliance stack.

The default dependency is appropriate for most Micronaut applications:

dependency:micronaut-validation[groupId="io.micronaut.validation"]

It validates using Micronaut introspection and compile-time metadata. It does not enable XML parsing, ServiceLoader bootstrap, or reflection fallback by default, and it has no Jakarta EL dependency. Add `micronaut-validation-el` to enable Jakarta EL interpolation.

== Jakarta Compliance Dependency

Use the aggregate module when an application, test suite, or library needs the Jakarta Validation provider bootstrap or other specification-oriented behavior:

dependency:micronaut-validation-jakarta[groupId="io.micronaut.validation"]

The aggregate explicitly includes `micronaut-validation-reflection`, bootstrap, XML, and the Jakarta EL implementation.

== Module Model

`micronaut-validation`::
The default lightweight validation implementation. It uses generated annotation metadata and bean introspections and remains free of XML, reflection fallback, and `jakarta.validation.spi.ValidationProvider` ServiceLoader registration. Jakarta EL interpolation is provided separately by `micronaut-validation-el`.

`micronaut-validation-reflection`::
Optional. Describes reflectively what the annotation processors never saw, through the `micronaut-reflection` module of Micronaut core: a type without a generated introspection, a constraint whose composition is not retained in the metadata, and the executables the Jakarta Validation API names by their `java.lang.reflect.Method` or `Constructor`. Without it the validator reads generated metadata only, including when a field carries `@ReflectiveAccess`. The reflective description of the types can be switched off with the system property `micronaut.validation.reflection.enabled=false`.

`micronaut-validation-bootstrap`::
Provides the Jakarta `ValidationProvider`, `Configuration`, and `ValidatorFactory` bootstrap integration used by `jakarta.validation.Validation`. It uses generated metadata first and has no dependency on `micronaut-validation-reflection`. Bootstrap classes without generated constructors require the optional reflection provider.

`micronaut-validation-xml`::
Adds support for `META-INF/validation.xml` and Jakarta constraint mapping XML resources. Classes, declaration signatures, annotation members, and access use generated metadata first. Missing metadata requires `micronaut-validation-reflection`; XML does not independently authorize reflection.

`micronaut-validation-el`::
Adds Micronaut Jakarta EL and its runtime interpreter. Message interpolation uses generated bean introspections and container resolvers, with direct locale-aware formatter dispatch. It does not add the EL reflection companion or reflective bean, record, or static-field resolvers. An EL API jar alone does not activate this integration.

`micronaut-validation-jakarta`::
Aggregates reflection, bootstrap, and XML support for the Jakarta compliance stack, and includes `micronaut-validation-el`. Types without a generated introspection are described through `micronaut-validation-reflection`.

== Choosing Modules

Prefer `micronaut-validation` when you want Micronaut's compile-time validation model and GraalVM-friendly defaults. Add `micronaut-validation-reflection` to it when the validator has to describe types, constraints or executables the processors never saw.

Use `micronaut-validation-jakarta` when you need Jakarta Validation bootstrap behavior, XML configuration, constraint mapping XML, Jakarta EL interpolation, or reflection fallback for specification compatibility.

You can also depend on individual optional modules when only one part of the compliance stack is required.

== EL Interpolation Without Reflection

dependency:micronaut-validation-el[groupId="io.micronaut.validation"]

This module uses Micronaut Jakarta EL `1.1.1-SNAPSHOT`, including the interpreter with its separate optional reflection companion. Configure the Micronaut snapshot repository when consuming this development version.

Annotate application beans with `@Introspected` for property expressions. Annotate methods with `@Executable` when expressions call them. The Jakarta `formatter.format(...)` variable is dispatched directly and supports the requested locale and variable arguments.

The default EL sandbox remains enabled. Group and payload variables retain their `Class` values. Only `name` and `simpleName` are exposed through a generated class introspection; reflective properties such as `classLoader` remain unavailable. An unresolved or disallowed expression is left unchanged. The integration intentionally omits reflective property resolvers even if another dependency adds the EL reflection companion; that companion may enable additional method execution subject to the sandbox.

Message interpolation expands user bundles recursively, applies provider messages, substitutes constraint attributes once, and evaluates EL expressions. Escaped text and substituted attribute values are never reinterpreted. Bundle cycles remain unresolved; nesting beyond 64 levels reports a validation error.
