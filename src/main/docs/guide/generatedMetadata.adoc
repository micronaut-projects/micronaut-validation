Micronaut Validation 5.3 requires Micronaut core 5.3 or later. Development uses the matching core 5.3 snapshot; release builds use the corresponding release.

Validation uses the existing Micronaut visitors and generated bean introspections and executable metadata. It does not add an annotation processor, emit annotation implementations or generate additional validation provider classes.

Validation keeps Micronaut `Argument` information through constraints, container extraction, and executable inheritance: annotations, nested generic arguments, raw types, wildcard bounds, and resolved type variables. Compile with `micronaut-validation-processor` to retain validation annotations in the normal Micronaut metadata. `ValidatedElement` marks the arguments that require traversal; unmarked branches are skipped.

== Field and Getter Access

By default, `@Introspected` selects method access. Constraints on a backing field are validated through its compatible generated property getter. Record components use their generated accessors. Ordinary bean properties and records do not require `@ReflectiveAccess`.

Selecting `accessKind = FIELD` requests direct field access. An accessible field then uses generated field access. When both `FIELD` and `METHOD` access are selected, each constrained declaration is validated against its own value. Distinct violations are retained even when their paths and messages are equal. Record component constraints are validated once during bean validation; their accessors remain available for executable return-value validation.

An inaccessible field requiring direct field access can authorize its own reflective read by carrying `io.micronaut.core.annotation.ReflectiveAccess`. This narrow exception belongs to the field itself: annotating the bean type or setting `@Introspected(visibility = ANY)` does not authorize it. Native-image registration for an annotated field is generated during compilation.

An inaccessible, unannotated field requiring direct access fails with a `ValidationException` describing the missing capability. Explicit field access does not substitute its getter. A getter with a different argument type also cannot supply a field declaration's value. Either authorize the field explicitly or add the optional provider:

dependency:micronaut-validation-reflection[groupId="io.micronaut.validation"]

The provider permits runtime discovery and invocation when generated metadata is unavailable. The system property `micronaut.validation.reflection.enabled=false` selects generated descriptions for the compatibility test profile; it does not remove modules from the classpath. To enforce absence of runtime reflection capabilities, exclude both `micronaut-validation-reflection` and core `micronaut-reflection` from the runtime classpath.

== Jakarta Signatures and Optional Modules

Jakarta operations accepting a caller-supplied `Method` or `Constructor` retain their signatures. Validation resolves their generated executable metadata. Operations that need to discover a runtime member require the reflection provider if metadata is unavailable. Ordinary Micronaut interception uses generated executable APIs.

Bootstrap and XML modules do not automatically add the reflection provider. XML mappings produce ordinary `AnnotationMetadata` and structural `Argument` values for the shared validation and descriptor implementation. Standard constraint members use the Jakarta API contracts. Runtime discovery of application annotation members, missing executable declarations, and concrete annotations for `ConstraintDescriptor.getAnnotation()` or Jakarta validator initialization require the optional reflection provider. Micronaut constraint validators consume `AnnotationValue` directly. The `micronaut-validation-jakarta` aggregate explicitly includes reflection for comprehensive Jakarta compatibility.

Ordinary group inheritance uses class assignability. Cascade conversion of inherited groups needs the requested group's generated hierarchy or the optional provider; a missing hierarchy produces a capability error. Duplicate requested groups are validated once.

The restricted TCK profile retains seven measured exclusions: core constructor metadata omits the enclosing-instance parameter of a non-static inner class, and six XML tests name private methods absent from standard introspections. It runs 1,047 tests. The full Jakarta stack uses the optional provider and tests all 1,054 cases, including these exclusions.

== Maintainer Verification

Production compilation treats NoReflection and NullAway diagnostics as errors. Compiler fixtures also prove that generated Java cannot bypass these gates. A separate worker classpath verifies the default stack without either reflection module.

The differential test suite uses Hibernate Validator 9.1.4.Final as a reference and Jakarta Validation 3.1 as the authority. It replays saved regressions and performs 2,000 generated comparisons during `check`. Run a larger campaign manually:

[source,bash]
----
./gradlew :micronaut-tests:micronaut-validation-differential:fuzzCampaign -PfuzzSeed=631530 -PfuzzCount=50000
----

Campaigns have a 30-minute deadline, configurable with `-PfuzzLimitMinutes`. Interrupted or timed-out campaigns are incomplete. Reproductions and campaign status are written under `tests/validation-differential/build/differential`; no recurring campaign is scheduled.

Run the native access smoke test with a GraalVM installation:

[source,bash]
----
GRAALVM_HOME=/path/to/graalvm ./gradlew :micronaut-validation:nativeSmoke
----
