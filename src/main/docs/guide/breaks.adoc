This section documents breaking changes between Micronaut Validation versions:

=== Micronaut Validation 5.3.0

* Micronaut core 5.3 is the minimum supported core version.
* Default validation no longer discovers or invokes arbitrary runtime members. Ordinary properties and records retain generated getter/accessor reads. An inaccessible field requiring direct field access needs `micronaut-validation-reflection`. `@ReflectiveAccess` provides native registration but no longer authorizes reflection in the default module.
* Bootstrap no longer adds the reflection provider transitively. Applications relying on reflection fallback must add `micronaut-validation-reflection` or use `micronaut-validation-jakarta`.
* When both field and method access are selected, field and getter constraints are evaluated against their own values. Separate declarations can produce violations with identical paths and messages; these violations retain their multiplicity.
* The default module no longer synthesizes annotation instances. Code using `ConstraintDescriptor.getAnnotation()`, or a Jakarta `ConstraintValidator` that implements `initialize(A)`, must add `micronaut-validation-reflection`. A Jakarta validator compiled with `micronaut-validation-processor` that keeps the default `initialize` needs no annotation instance and works without it. Micronaut validators continue to use `AnnotationValue` and the generated metadata directly.
* The deprecated `DefaultValidatorConfiguration.getClassFromType(Type)` is retained. Non-class runtime signatures require `micronaut-validation-reflection`; use `Argument.getType()` for generated metadata.
* `ConstraintDescriptor.getAttributes()` returns typed values. Enum attributes without generated value support, and nested-annotation constraint attributes, require the reflection companion there; missing support fails explicitly instead of returning incorrectly typed attributes. Message interpolation does not need them: a message renders the value held in the metadata, the enum constant's name.
* A type compiled without `micronaut-validation-processor` 5.3, such as a library type or one introspected through `@Introspected(classes = ...)`, is validated with the constraints of its introspection and no separately validated super types, as before 5.3.
* Passing a `java.lang.reflect.Method` to validation needs `micronaut-validation-reflection` when Micronaut has to look that method up itself. This applies to method interception with a `ValidatorFactory` that is not Micronaut's own, such as a replaced provider, and to a custom Jakarta `ParameterNameProvider`. The default validator and the default parameter name provider use generated executable metadata and are not affected.
* An invalid constraint definition is reported by the annotation processor as a warning. Set the annotation processor option `micronaut.validation.strictConstraintDefinitions=true` to make it a compilation error.
* A constraint mapping XML file containing an element the mapping schema does not allow where it stands is rejected with a `ValidationException`. Such an element was previously ignored.
* Inherited group conversion needs a generated hierarchy for the requested group or the optional reflection provider. Missing capabilities produce a clear error.
* Jakarta EL interpolation requires `micronaut-validation-el` (also included by `micronaut-validation-jakarta`). Adding an EL API or implementation alone does not replace the basic interpolator.

=== Micronaut Validation 5.0.0

- The api:validation.validator.DefaultValidator[] methods `requireNonNull(String, T)` and `requireNonEmpty(String, String)` deprecated previously and are no longer exposed as part of the public API.

- The api:validation.validator.constraints.ConstraintValidator[] method `getMessageTemplate())` and `requireNonEmpty(String, String)` deprecated previously is removed. It was unused and has no replacement.
